# v1.10.1 发行说明

## 概述

v1.10.1 是一次以重构优化和安全修复为核心的版本。本版本修复 9 个依赖安全漏洞（含 6 个 High）；对前端组件进行大规模重构，引入配置驱动的 DNS 记录表单、路由懒加载和构建分 chunk 优化；拆分 domainStore 为 slice 架构提升可维护性；同时升级 Rust 核心依赖（reqwest 0.13、rmcp 1.2、sea-orm 2.0.0-rc.37 等），修复批量删除后记录未重新加载的问题，并优化 CI/CD 发布流程顺序。

## 安全修复

### 🔒 依赖安全漏洞修复

本版本通过依赖升级修复 9 个安全漏洞：

**High 级别（6 个）**：

| 漏洞 | 依赖 | 修复版本 |
|------|------|----------|
| PKCS7_verify Certificate Chain Validation Bypass | aws-lc-sys | 0.37.1 → 0.39.0 |
| Timing Side-Channel in AES-CCM Tag Verification | aws-lc-sys | 0.37.1 → 0.39.0 |
| PKCS7_verify Signature Validation Bypass | aws-lc-sys | 0.37.1 → 0.39.0 |
| X.509 Name Constraints Bypass via Wildcard/Unicode CN | aws-lc-sys | 0.37.1 → 0.39.0 |

| Unauthenticated Remote DoS via QUIC Transport Parameter Parsing | quinn-proto | 0.11.13 → 0.11.14 |

**Moderate 级别（3 个）**：

| 漏洞 | 依赖 | 修复版本 |

## Bug 修复

### 🐛 批量删除后记录未重新加载

修复批量删除 DNS 记录后，如果本地记录已清空但服务器仍有数据时未自动重新加载的问题：
- 批量删除完成后检测本地剩余记录数
- 当本地为空但总数大于 0 时，自动重新获取记录列表

## 重构与优化

### 📋 DNS 记录表单配置驱动化

将 DNS 记录表单从 switch-case 硬编码重构为配置驱动模式：

- 新增 `record-type-configs.ts` 配置文件，声明每种记录类型的字段、默认值和主值键
- 表单组件代码从 600+ 行精简至约 300 行
- 新增记录类型只需添加配置项，无需修改渲染逻辑

### 📂 前端组件目录结构重组

按职责细分组件目录，提升代码组织性：

- `account/` → `accounts/`（含 `form/`、`io/` 子目录）
- `domain/` → `domains/`（含 `batch/`、`metadata/` 子目录）
- DNS 记录表格抽取 `DeleteDialogs`、`DnsPagination`、`useInfiniteScroll` 独立模块
- `DomainBatchActionBar` 从 330 行重构为 94 行，标签操作抽取为 `TagOperationDialog`

### 🧩 domainStore Slice 拆分

将臃肿的 `domainStore` 拆分为职责单一的 slice 模块：

- `domainBatchSlice.ts` — 批量选择与批量标签操作
- `domainFilterSlice.ts` — 标签筛选
- `domainMetadataSlice.ts` — 元数据操作（收藏、标签、颜色等）
- `domainUiSlice.ts` — UI 状态（展开状态、滚动位置）
- `domainStore.types.ts` — 类型定义独立文件

### ⚡ 前端性能优化

**路由懒加载**：所有页面组件改为动态导入，减少首屏加载体积

**Vite 构建分 chunk**：
- `vendor-react` — React/ReactDOM/React Router
- `vendor-radix` — Radix UI 组件库
- `vendor-tauri` — Tauri API
- `vendor-i18n` — i18next 国际化

### 🔧 工具箱组件统一

工具箱各页面（DnsLookup、DnsPropagation、DnssecCheck、SslCheck）统一使用 `QueryInput` 组件，消除重复的历史记录芯片和回车键处理代码。

## CI/CD 改进

### 📦 发布流程顺序优化

调整 Release workflow 执行顺序：先完成 GitHub Release 发布，再更新 Homebrew Cask 和 Formula，避免包管理器指向尚未发布的版本。

## 升级说明

从 v1.10.0 升级到 v1.10.1 需注意以下事项：

### 对开发者

1. **reqwest feature 变更**：TLS feature 从 `rustls-tls` 改为 `rustls`
2. **rmcp API 变更**：`ServerInfo` 改为 builder 模式，`CallToolRequestParams` 构造函数签名变更
3. **rand API 变更**：`RngCore` trait 替换为 `Rng` trait

### 对用户

1. **功能兼容**：所有现有功能保持不变
2. **数据兼容**：无需数据迁移
3. **安全增强**：修复 9 个依赖安全漏洞
4. **性能提升**：前端首屏加载更快
